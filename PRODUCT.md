# Product

## Platform

ios

A native macOS app in SwiftUI and AppKit (deployment target macOS 26, the Liquid Glass era). The schema has no value for the Mac; `ios` is the nearest, since it names Apple's design language. Apple's macOS HIG is the reference for native expectations, so iPhone-only guidance (touch targets, Dynamic Type, edge swipes, the home indicator) doesn't apply.

## Users

The author first, for their own daily spaced-repetition study; other Mac users who already study with Anki come later. They know Anki's model (decks, notes, cards, the new/learn/review queues, FSRS) and are not new learners, so first-run onboarding is not a priority yet.

## Product Purpose

AnkiMac is a native macOS frontend for Anki. It runs the upstream Rust core (`rslib`) unchanged, so scheduling, sync and the collection format are Anki's own, and replaces only the interface. Success means studying in it every day in place of Anki desktop, losing nothing.

## Positioning

Three things Anki desktop (a Qt app) can't truthfully claim together:

- **Native on macOS:** SwiftUI, Mac menus, shortcuts, window behaviour and system appearance, not a cross-platform port.
- **Faster:** measured against the official desktop app as baseline (`bench/`).
- **Calmer to study in:** a quieter, more considered interface than desktop's (for example the Today view of what's due across the collection).

## Operating Context

- Daily review sessions, often long, driven from the keyboard.
- Collection management around them: the Browser, the note editor, Add Cards, deck options, statistics, import/export, profiles and sync.
- The same collection and AnkiWeb sync as desktop and AnkiDroid, so users move between apps.

## Capabilities and Constraints

- Goal is feature parity with Anki desktop; features come before deep performance work.
- Cards render in a WKWebView running upstream's `reviewer.js` and CSS, with the note type's own templates; card content styling belongs to the user's note types, not the app.
- Every colour, size and spacing value lives in `App/AnkiMac/Theme.swift`.
- UI strings come from Anki's translations (`App/AnkiMac/Generated/Tr.swift`, generated by `scripts/gen-strings.py`).
- Licence: AGPL-3.0-or-later, same as Anki.
- Undecided: public release, distribution channel, and whether onboarding for new Anki users is ever in scope.

## Brand Commitments

- Name: AnkiMac. App icon at `App/AnkiMac/AnkiMac.icon`.
- Anki's queue colours stay recognisable: new blue, learning red, review green.
- Copy uses upstream Anki's terms and translations rather than new wording.

## Evidence on Hand

- Benchmark harness and results against desktop Anki in `bench/` (`bench/results/`).
- No users, testimonials or public release yet; don't claim any.

## Product Principles

1. **Parity first.** Nothing a desktop user relies on goes missing; a feature isn't done until it does what desktop does.
2. **Mac-native over Anki-familiar chrome.** Follow macOS conventions for windows, menus and controls; keep Anki's concepts, terms, keys and queue colours.
3. **The keyboard runs study.** Every study action works from the keyboard with desktop's keys.
4. **Quiet by default.** The interface recedes during study; the card and the counts are what matter.
5. **Measured speed.** Faster than desktop is a claim backed by `bench/`, not a feeling.

## Accessibility & Inclusion

Keyboard-first study is required. Follow the system appearance (light and dark) and macOS accessibility settings.
